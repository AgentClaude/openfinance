# OpenFinance Deployment Guide

## Quick Start

```bash
# 1. Clone and enter the repo
git clone https://github.com/AgentClaude/openfinance.git
cd openfinance

# 2. Run setup (generates secrets, builds images, starts everything)
chmod +x deploy/deploy.sh deploy/backup.sh
./deploy/deploy.sh setup

# 3. Edit .env.production with your domain
#    For Tailscale: DOMAIN=your-hostname.tailnet-name.ts.net
#    For public domain: DOMAIN=finance.yourdomain.com

# 4. Restart with the correct domain
docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d
```

## Services

| Service | Purpose | Port |
|---------|---------|------|
| **caddy** | Reverse proxy + auto HTTPS | 80, 443 |
| **api** | Rails 8 API (GraphQL + REST) | 3001 (internal) |
| **web** | React SPA (nginx) | 3000 (internal) |
| **sidekiq** | Background jobs | — |
| **db** | PostgreSQL 16 | 5432 (internal) |
| **redis** | Cache + job queue | 6379 (internal) |

## Deployment Options

### Option 1: Tailscale (Recommended for Self-Hosting)

The easiest way to self-host securely without exposing ports to the internet.

```bash
# Install Tailscale on your server
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up

# Get your Tailscale hostname
tailscale status

# Set DOMAIN in .env.production
DOMAIN=your-hostname.tailnet-name.ts.net

# Caddy will auto-generate a local CA certificate
# All devices on your tailnet can access the app
```

### Option 2: Tailscale Serve (Zero Config HTTPS)

```bash
# Serve OpenFinance via Tailscale's built-in HTTPS
tailscale serve https / http://localhost:3002

# This gives you a valid HTTPS URL on your tailnet
# No Caddy needed — use docker-compose.yml directly
```

### Option 3: Public Domain

```bash
# Point your domain's A/AAAA record to your server IP
# Set DOMAIN in .env.production
DOMAIN=finance.yourdomain.com

# Caddy will automatically obtain Let's Encrypt certificates
# Ensure ports 80 and 443 are open in your firewall
```

### Option 4: VPS (DigitalOcean, Hetzner, etc.)

```bash
# On a fresh Ubuntu 22.04+ VPS:
apt update && apt install -y docker.io docker-compose-plugin git
git clone https://github.com/AgentClaude/openfinance.git
cd openfinance
./deploy/deploy.sh setup
# Edit .env.production, then restart
```

## Commands

```bash

docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d

# View status
./deploy/deploy.sh status

./deploy/deploy.sh logs

./deploy/backup.sh

./deploy/backup.sh --restore latest

# List backups
./deploy/backup.sh --list

# Prune old backups (keep last 30 days)
./deploy/backup.sh --prune 30
```

## Backups

### Automated Daily Backups

Add to crontab (`crontab -e`):

```cron
# Daily backup at 2am
0 2 * * * cd /path/to/openfinance && ./deploy/backup.sh >> /var/log/openfinance-backup.log 2>&1

# Weekly prune (keep 30 days)
0 3 * * 0 cd /path/to/openfinance && ./deploy/backup.sh --prune 30
```

### Offsite Backups

Sync backups to a remote location:

```bash
# rsync to another machine
rsync -avz backups/ user@backup-server:/backups/openfinance/

# Or use rclone for S3/B2/etc
rclone sync backups/ remote:openfinance-backups/
```

## Environment Variables

See `.env.production` (generated by `deploy.sh setup`) for all configuration options.

**Required:**
- `DOMAIN` — Your domain or Tailscale hostname
- `POSTGRES_PASSWORD` — Database password (auto-generated)
- `SECRET_KEY_BASE` — Rails secret (auto-generated)
- `JWT_SECRET_KEY` — Auth token secret (auto-generated)

**Optional:**
- `PLAID_CLIENT_ID` / `PLAID_SECRET` — For bank connectivity
- `SMTP_*` — For email notifications
- `ENABLE_PLAID` — Set to `true` to enable Plaid

## Plaid Setup

1. Create a Plaid account at [plaid.com](https://plaid.com)
2. Get your Client ID and Secret from the dashboard
3. Set in `.env.production`:
   ```
   ENABLE_PLAID=true
   PLAID_CLIENT_ID=your_client_id
   PLAID_SECRET=your_secret
   PLAID_ENVIRONMENT=development  # or production
   PLAID_WEBHOOK_URL=https://your-domain.com/webhooks/plaid
   ```
4. Restart: `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d`

## Troubleshooting

### API won't start
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs api
# Common: missing RAILS_MASTER_KEY or database not ready
```

### SSL certificate issues
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml logs caddy
# Ensure DNS A record points to your server IP
# Ensure ports 80/443 are open
```

### Database migration stuck
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api bundle exec rails db:migrate:status
docker compose -f docker-compose.yml -f docker-compose.prod.yml exec api bundle exec rails db:migrate
```

### Reset everything
```bash
docker compose -f docker-compose.yml -f docker-compose.prod.yml down -v
./deploy/deploy.sh setup
```

## Security Notes

- Database and Redis are not exposed externally (ports removed in prod override)
- Caddy handles SSL termination automatically
- All secrets are auto-generated during setup
- PostgreSQL uses `scram-sha-256` authentication in production
- Security headers (HSTS, X-Frame-Options, etc.) are set by Caddy
- GraphQL Playground is disabled in production
- API docs are disabled by default in production
